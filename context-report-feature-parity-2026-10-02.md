- **Purpose**: Subprocess wrapper invoking the official pycparser-based MQIL self-composition transpiler.

  - `generate_miter_program(source_c_path, input_json_path, output_miter_path)`: Lines 15–46.

  - Asserts that both input source C and JSON exist, and verifies that `output_miter_path` exists upon completion.

#### 4. [`tools/cbmc_mqil/src/main.py`](file:///c:/Users/sujit/OneDrive/Documents/FP/tools/cbmc_mqil/src/main.py)
- **Purpose**: Official MQIL Abstract Syntax Tree (AST) transformer (Panigrahi & Karfa). Transforms a single C program into a 2-safety self-composition miter ($P_1 \times P_2$).
- **Key Logic**:
  - Lines 37–41: Detects mock libc header directory `tools/fake_libc/` and adds `-nostdinc -Itools/fake_libc` to `pycparser`'s preprocessor arguments.
  - Lines 42–49: Parses input C source into an AST; extracts global variables and struct definitions.
  - Lines 57–95: Duplicates functions (via `FuncDefHandler2`) and global declarations (via `Renamer`).
  - Lines 99–104: Injects high-input inequality assumptions (`AddAssumeCalls`) and state equality assertions (`AddAssertCalls`).
  - Line 109: Generates miter C source using `c_generator.CGenerator()`.

#### 5. [`src/core/cbmc_runner.py`](file:///c:/Users/sujit/OneDrive/Documents/FP/src/core/cbmc_runner.py)
- **Purpose**: Formal model checking bridge. Executes native Windows CBMC or Ubuntu WSL CBMC with `--unwind 5`.
- **Key Function**:
  - `run_cbmc_verification(miter_file_path, unwind=5, timeout=45)`: Lines 21–74.
  - Runs `wsl -d Ubuntu cbmc <miter_path> --unwind 5`.
  - Regex parses output for `[*.assertion.*] ... (SUCCESS|FAILURE)`.
  - Fallback regex parses `** X of Y failed`.
  - **Silent Failure Flaw (K1)**: Lines 36–38 execute `subprocess.run()`, but never assert `proc.returncode == 0`. Syntax errors, conversion errors, and typecheck failures produce 0 matched assertions and silently report `#leak = 0` (zero leakage).

- **Key Classes & Functions**:

  - `SecurityFlowVisitor(c_ast.NodeVisitor)`: Lines 96–190. Tracks explicit flows, culprit blocks, implicit flows, information leaks, prints, and array accesses.
  - `clean_c_code_for_pycparser(source_code)`: Lines 192–198. Regex-strips block comments, line comments, and `#include` directives.
  - `parse_c_ast(file_path)`: Lines 200–215. Attempts parsing with `pycparser.parse_file` using `fake_libc` include flags; falls back to `clean_c_code_for_pycparser` with comment/assert stripping.
  - `extract_group_a_features(source_c_path)`: Lines 217–236. Runs `MiterStructureVisitor` on `source_c_path`.
  - `extract_group_b_features(source_c_path, input_json_path, miter_c_path=None)`: Lines 238–271. Runs `SecurityFlowVisitor` on `source_c_path`; counts assumptions and assertions from `miter_c_path` text via regex.
  - `extract_all_mqil_features(source_c_path, input_json_path, miter_c_path=None)`: Lines 273–291. Combines Group A, Group B, and computes 3 normalized ratios.
  - `ProgramFeatureExtractor`: Lines 293–341. High-level class interface with path auto-discovery.

## 6. Decisions Needed

The following 11 architectural decisions must be made before implementing fixes:

### 1. Group A Target: Measure on Source or on Miter?
- **Option A (Miter)**: Follows the IEEE MQIL research paper (Table I & II) and handwritten specification. Matches existing values in `datasets/stage2_pipeline/dataset.csv`.
- **Option B (Source)**: Reflects raw program characteristics before code duplication. Matches current implementation in `src/core/feature_extractor.py`.
- **Recommended Default**: **Option A (Miter)**, aligning with the theoretical foundation of the research paper and existing CSV data.

### 2. Group B Target & Suffix Mapping
- **Option A (Source)**: Taint tracking on source using bare names (`pin`, `seed`). Simple, matches developer intent.
- **Option B (Miter)**: Taint tracking on miter using suffixed names (`pin_1`, `pin_2`). Captures duplicated paths but increases AST complexity.
- **Recommended Default**: **Option A (Source)** for AST data-flow, with regex counting of assumptions/assertions on the miter.

### 3. Taint Propagation Scope
- **Option A (Direct Only)**: Current implementation. Fails on structs, arrays, and functions.
- **Option B (Full Transitive)**: Support `c_ast.StructRef`, `c_ast.ArrayRef`, `c_ast.UnaryOp` (`++`), and inter-procedural parameter mapping.
- **Recommended Default**: **Option B (Full Transitive)**.

### 4. Definition of `num_implicit_flows`
- **Option A (Branch Count)**: Increment $+1$ per culprit block (current behavior).
- **Option B (Statement Count)**: Count total executable statements executed conditionally inside culprit blocks.
- **Recommended Default**: **Option B (Statement Count)**, matching the documented specification in `docs/02_SOURCE_SECURITY_FEATURE_EXTRACTION.md`.

### 5. Definition of `num_information_leak`
- **Option A (Tainted Variables Count)**: Increment whenever any variable becomes tainted (current behavior).
- **Option B (Output Reaching Count)**: Increment only when tainted data flows to observable variables, return values, or prints.
- **Recommended Default**: **Option B (Output Reaching Count)**.

### 6. Scope of `num_secret_dependent_prints`
- **Option A**: Match only standard C print calls (`printf`, `puts`, `putchar`).
- **Option B**: Match both standard calls and miter helpers (`printf_2`).
- **Recommended Default**: **Option A**, filtering out synthetic miter artifacts.

### 7. Assertion Counting & Prototype Exclusion
- **Option A**: Keep simple regex `assert\s*\(` (counts prototype $+1$).
- **Option B**: Use strict word-boundary matching `\bassert\s*\(` and exclude prototypes.
- **Recommended Default**: **Option B**, ensuring exact assertion counts.

### 8. Scope of `num_variables`
- **Option A**: Count all declarations in translation unit including mock libc headers (current behavior = 48).
- **Option B**: Exclude declarations from `tools/fake_libc` headers, counting only program variables (true count = 24).
- **Recommended Default**: **Option B**.

### 9. Counting Rule for `num_structure` and `num_union`
- **Option A**: Count both definitions and declarations (current behavior = 2 each).
- **Option B**: Count only definitions or only instance declarations.
- **Recommended Default**: **Option A** (consistently maintained across datasets).

### 10. Trailing Newline & `loc` Convention
- **Option A**: Standard Python `len(text.splitlines())`.
- **Option B**: Count raw newline characters `text.count('\n') + 1`.
- **Recommended Default**: **Option A** (`splitlines()`), which is standard across Python data processing libraries.

### 11. Macro Expansion Policy
- **Option A**: Preprocess macros with CPP (current behavior for `assume`).
- **Option B**: Textual regex preservation.
- **Recommended Default**: **Option A** (standard AST parsing pipeline).
