## I. Summary Section

### 10-Line Executive Summary
1. The project predicts Quantitative Information Leakage (`#leak`) of whole C programs via supervised machine learning without running formal solvers at inference.
2. Dataset generation synthesizes C programs across 10 architectural leakage families (zero, direct, partial, implicit, arithmetic, bitwise, branches, loops, arrays, mixed).
3. Every C program is paired with a companion JSON specifying input variables partitioned into sensitive secrets (`high_vars`) and public inputs (`low_vars`).
4. Ground truth is generated by transpiling the program into a 2-safety self-composition miter ($P_1 \times P_2$) using an AST engine (`tools/cbmc_mqil/src/main.py`).
5. In the miter, public inputs are equated, high inputs are asserted unequal (`__CPROVER_assume(h1 != h2)`), and equality assertions (`assert(v1 == v2)`) check state leaks.
6. The CBMC Bounded Model Checker (`v6.6.0` via Ubuntu WSL) verifies the miter; `#leak` equals the count of failed equality assertions.
7. Static features (Group A: structure, Group B: taint flows, Group C: normalized ratios) are extracted using `pycparser` AST visitors.
8. Severe bugs currently corrupt feature extraction: `SecurityFlowVisitor` lacks inter-procedural taint propagation, causing 0 culprit blocks/implicit flows across all datasets.
9. Severe transpiler bugs crash external programs: `union` tag duplication, `assert_2`/`printf_2` undefined calls, `main(void)` generating invalid C syntax `void main(void None_1, void None_2)`, and string literal indexing bugs (`idx_name`).
10. Family-grouped splitting isolates zero-leakage programs exclusively to the test set, producing negative $R^2$ scores across all trained regression models.

### 11. Generation Logic Details
- **Non-Technical Explanation**: The generator creates small C programs testing different ways a secret password or key could accidentally leak to an unauthorized observer. For example, some programs multiply the secret by 0 (zero leak), some output the secret directly (full leak), some disguise it with bitmasks or math, and some let the secret decide an `if-else` path. Each program has an accompanying JSON listing which variables are secrets.
- **Technical Implementation**:
  - The generator [`src/generator/synthesizer.py`](file:///c:/Users/sujit/OneDrive/Documents/FP/src/generator/synthesizer.py) iterates over 10 distinct algorithmic families:
    1. `zero_leakage`: `temp = (secret + k) * 0; return pub_val;`
    2. `direct_leakage`: `t1 = secret + k; return t1 - k + pub_val;`
    3. `partial_leakage`: `return ((secret >> shift) & mask) + pub_bias;`
    4. `implicit_flow`: `if (secret > threshold) flag = 10; else flag = 20; return flag + pub;`
    5. `arithmetic`: `return (((secret * mult + bias) % 256) * pub_scale);`
    6. `bitwise`: `x = (secret ^ mask) << rot; return x ^ nonce;`
    7. `nested_branches`: Multi-tier if-else categorization on secret thresholds.
    8. `loop_accumulator`: Loop accumulating secret bits: `acc += ((secret >> i) & 1);`
    9. `array_lookup`: Table indexing: `return lookup_table[secret % 4] + pub_base;`
    10. `mixed_control_data`: Hybrid loops, arrays, and branch conditions.
  - Every program includes global state variables, helper functions, and an uninitialized symbolic `main()` entrypoint.

### 12. Synthetic / LLM Generation
- **LLM Usage**: None. All benchmarks are generated deterministically using parameterized Python format strings.
- **Cost / API Quotas**: $0.00. No external API calls.

### 13. Labeling / Annotation Logic
- **Ground Truth Source**: Formal verification via the CBMC Bounded Model Checker (`v6.6.0`).
- **Mechanism**:
  - In the transpiled miter program ($P_1 \times P_2$), high-security inputs are assumed unequal:
    ```c
    __CPROVER_assume(h_1 != h_2);
    ```
  - Low-security inputs are assumed equal:
    ```c
    __CPROVER_assume(l_1 == l_2);
    ```
  - Equality assertions are placed on all internal and output variables:
    ```c
    assert(v_1 == v_2);
    ```
  - If a secret affects variable $v$, CBMC finds a counterexample and marks the assertion `FAILURE`.
  - The ML target label `#leak` (`actual_mqil_leakage`) is the integer sum of failed assertions.

### 14. Randomness & Reproducibility
- **Seeds**: Parameter variations are strictly derived from loop indices `k` ($k \in [0, \text{count}-1]$).
- **Hashing**: SHA-256 hashes of generated source strings are tracked in a set; collisions trigger an assertion error:
  ```python
  code_hash = hashlib.sha256(c_code.strip().encode("utf-8")).hexdigest()
  assert code_hash not in seen_hashes, f"Duplicate program detected: {pid}"
  ```
- **Nondeterminism**: Re-running generation yields 100% byte-for-byte identical output.

## D. Extraction Logic

### 15. What is Being Extracted
- **Extraction Targets**:
  1. **Group A (Program Structure)**: `loc`, `num_instructions`, `num_branches`, `num_loops`, `num_functions`, `num_variables`, `num_arrays`, `num_structure`, `num_union`.
  2. **Group B (Security Features)**: `num_high_inputs`, `num_low_inputs`, `num_explicit_flows`, `num_culprit_blocks`, `num_implicit_flows`, `num_information_leak`, `num_secret_dependent_prints`, `num_assumptions`, `num_assertions`, `num_array_accesses`.
  3. **Group C (Normalized Ratios)**: `taint_ratio`, `secret_branch_ratio`, `secret_memory_ratio`.
- **Extraction Tools**:
  - `pycparser` C Abstract Syntax Tree (AST) parsing.
  - AST visitors: `MiterStructureVisitor` and `SecurityFlowVisitor` in [`src/core/feature_extractor.py`](file:///c:/Users/sujit/OneDrive/Documents/FP/src/core/feature_extractor.py).
  - Regular expressions for counting `__CPROVER_assume` and `assert` statements in miter text.

### 16. Edge Cases Handled vs. NOT Handled
- **Handled**:
  - Stripping C comments (`/* ... */` and `// ...`).
  - Preprocessor include stripping or redirection via mock headers in [`tools/fake_libc/`](file:///c:/Users/sujit/OneDrive/Documents/FP/tools/fake_libc/).
  - Bounded loops up to `--unwind 5`.
- **NOT Handled (Known Gaps)**:
  - **Inter-procedural function calls**: `SecurityFlowVisitor` fails to map call arguments in `main` to formal parameters in helper functions.
  - **Implicit flow taint propagation**: Variables assigned inside secret-controlled branches are not marked as tainted.
  - **Union type comparisons**: Transpiler emits `assert(reg_1 == reg_2);` for union types, which is illegal in C.
  - **Functions with `void` parameter lists**: `int main(void)` triggers a regex/string naming bug resulting in `void main(void None_1, void None_2)`.
  - **Secret-dependent array indexing**: `visit_ArrayRef` increments `num_array_accesses` on *every* array access, regardless of whether the index is secret-dependent.
  - **Pointer aliasing**: Pointers to structures are not tracked through memory.

### 17. Error Handling & Silent Data Loss
- **CRITICAL RISK — Silent Data Loss in CBMC Runner**:
  - In [`src/core/cbmc_runner.py:37-74`](file:///c:/Users/sujit/OneDrive/Documents/FP/src/core/cbmc_runner.py#L37-L74), if CBMC crashes, type-checks with errors, or fails to parse a miter, `proc.returncode` is not checked.
  - The regex matches 0 failed assertions and 0 total assertions.
  - The runner returns `actual_mqil_leakage = 0` and `actual_mqil_assertions_total = 0`.
  - The pipeline logs `[OK] CBMC Ground Truth: #leak = 0` and writes this corrupted result into the dataset without raising an exception!
